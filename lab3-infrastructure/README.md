# CI/CD Pipeline for NestJS Application

Цей репозиторій містить конфігурацію інфраструктури та Continuous Delivery (CD) pipeline для автоматизованого розгортання NestJS застосунку. Проєкт реалізує патерн "Separation of Concerns", розділяючи середовище розгортання та середовище керування пайплайнами.

## Архітектура Інфраструктури

Інфраструктура розгортається локально за допомогою Vagrant і складається з двох ізольованих віртуальних машин (Ubuntu 22.04):

1. **Target Node (`target`)**: "Продакшн" сервер. Тут автоматично встановлюються Nginx (Reverse Proxy), MariaDB (база даних) та Docker. Застосунок розгортається в Docker-контейнері під керуванням `systemd`.
2. **Runner Node (`runner`)**: Сервер керування пайплайнами. Містить локальний агент GitHub Actions. Взаємодіє з Target Node виключно по SSH. З міркувань безпеки, на цій машині відсутній код самого застосунку чи конфігурації Nginx.

---

## Інструкція з розгортання

### Етап 1: Підготовка інфраструктури

Скрипти провіжнингу (`setup-target.sh` та `setup-runner.sh`) запускаються автоматично під час першого підняття машин.

1. Скопіюйте **попередньо форкнутий** репозиторій та перейдіть у робочу директорію.
2. Підніміть віртуальні машини:

   ```bash
   vagrant up
   ```

3. Дізнайтеся IP-адресу цільової машини (знадобиться пізніше):
   ```bash
   vagrant ssh target -c "hostname -I"
   ```

### Етап 2: Налаштування доступу (SSH)

GitHub Runner повинен мати безпарольний доступ до Target Node для виконання команд розгортання.

1. Зайдіть на машину ранера:
   ```bash
   vagrant ssh runner
   ```
2. Згенеруйте SSH-ключ:
   ```bash
   ssh-keygen -t ed25519 -N "" -f ~/.ssh/id_ed25519
   ```
3. Передайте ключ на Target Node (замініть `<TARGET_IP>` на IP, отриманий на Етапі 1). _Стандартний пароль для копіювання — `vagrant`_:
   ```bash
   ssh-copy-id vagrant@<TARGET_IP>
   ```

### Етап 3: Реєстрація GitHub Runner

Щоб уникнути зберігання приватних токенів у репозиторії, реєстрація ранера виконується вручну.

1. Знаходячись на машині `runner`, перейдіть у підготовлену директорію:
   ```bash
   cd ~/actions-runner
   ```
2. Отримайте токен реєстрації в налаштуваннях вашого GitHub репозиторію (**Settings -> Actions -> Runners -> New self-hosted runner**).
3. Виконайте конфігурацію (вставте команду `config.sh` з GitHub):
   ```bash
   ./config.sh --url https://github.com/<ваш-репозиторій> --token <ВАШ_ТОКЕН>
   ```
4. Встановіть та запустіть ранер як фонову службу:
   ```bash
   sudo ./svc.sh install
   sudo ./svc.sh start
   ```
5. Вийдіть з віртуальної машини (`exit`).

### Етап 4: Налаштування змінних GitHub

Оскільки IP-адреси в мережі Vagrant/libvirt видаються динамічно, в коді немає хардкоду.

1. Перейдіть у репозиторії в **Settings -> Secrets and variables -> Actions**.
2. Відкрийте вкладку **Variables**.
3. Створіть нову змінну з назвою `TARGET_IP` і вставте IP-адресу цільової машини.

---

## Запуск розгортання

Continuous Delivery пайплайн (`cd.yml`) налаштований на автоматичний запуск при створенні анотованого тегу.

1. Зробіть коміт зі змінами.
2. Створіть і відправте тег версії:
   ```bash
   git tag -a v1.0.0 -m "Release v1.0.0"
   git push origin v1.0.0
   ```
3. Перейдіть у вкладку **Actions** на GitHub, щоб спостерігати за процесом збірки, розгортання та автоматичної верифікації.

---

## Верифікація та Безпека

- **Міграції баз даних:** Виконуються автоматично в ефемерному Docker-контейнері (через `ExecStartPre` у `systemd-unit`) перед стартом основного застосунку.
- **Healthchecks:** Верифікація розгортання здійснюється шляхом запиту на `http://<TARGET_IP>/health/ready`.
- **Nginx Security:** Доступ до endpoint-у `/health` на Target Node обмежено за допомогою White-list. Запити дозволені лише з внутрішніх підмереж (`192.168.121.0/24` та `192.168.122.0/24`). Усі зовнішні запити отримують HTTP статус `403 Forbidden`.
