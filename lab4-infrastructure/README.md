# Лабораторна робота №4: Автоматизація розгортання розподіленої інфраструктури

## Опис проекту

Проект реалізує автоматизацію розгортання розподіленого веб-застосунку (NestJS + MariaDB) з Лабораторної роботи №1 у локальному гіпервізорі KVM/libvirt. Конфігурація повністю побудована на принципах **Infrastructure as Code (IaC)**.

### Стек та інструменти:

- **Terraform**: Створення та оркестрація віртуальних машин у KVM, автоматична генерація динамічного інвентаря для Ansible.
- **Ansible**: Декларативне керування конфігурацією та деплой додатка.
- **Компоненти інфраструктури**:
  - **`db-node` (Ubuntu 22.04)**: Сервер бази даних MariaDB. Доступ повністю обмежений на мережевому рівні (UFW) та на рівні СУБД (Grants) — підключення дозволено **виключно** для IP-адреси `worker-node`.
  - **`worker-node` (Ubuntu 22.04)**: Веб-сервер додатка на базі **Node.js v24**. Застосунок NestJS працює через системний сокет (**Systemd Socket Activation**), а весь зовнішній трафік проксіюється через **Nginx Reverse Proxy** із захисним блокуванням роуту `/health`.

## Інструкція із запуску інфраструктури

### 1. Крок 1: Підняття віртуальних машин (Terraform)

Перейдіть у директорію Terraform, ініціалізуйте провайдер та запустіть створення машин:

```bash
cd terraform
terraform init
terraform apply -auto-approve
```

_Після завершення Terraform автоматично створить файл `ansible/inventory.ini`, прописавши туди актуальні IP-адреси, виділені DHCP-сервером KVM._

### 2. Крок 2: Автоматична конфігурація та деплой (Ansible)

Перейдіть у директорію Ansible та запустіть конфігураційний плейбук:

```bash
cd ../ansible
ansible-playbook -i inventory.ini playbook.yml

```

## Перевірка виконання вимог ТЗ

Всі перевірки виконуються з хост-машини (Fedora):

### 1. Перевірка повної ізоляції Бази Даних (Вимога ТЗ)

Спробуйте підключитися до MariaDB напрямую з хоста:

```bash
mysql -u mywebapp -h <IP_DB_NODE> -p
```

_Результат_: Запит зависає і відвалюється по таймауту. UFW фаєрвол та MariaDB повністю блокують хост-машину та будь-які інші сторонні IP. База доступна лише для `worker-node` та `db-node`.

### 2. Перевірка роботи додатка через Reverse Proxy (Nginx)

Виконайте запити до веб-сервера воркера на стандартний порт 80:

```bash
# Тест 1: Звичайний API запит (Отримання JSON)
curl http://<IP_WORKER_NODE>/notes
# Повертає пустий масив `[]` від NestJS, що підтверджує успішний зв'язок додатка з базою даних.

# Тест 2: Запит із вимогою HTML структури (Імітація браузера)
curl -H "Accept: text/html" http://<IP_WORKER_NODE>/notes
# Повертає згенеровану NestJS HTML-таблицю <table>.
```

### 3. Перевірка Health Checks

ППеревірте ендпоінти життєздатності та готовності системи:

```bash
# Тест Liveness probe (чи живий додаток)
curl http://<IP_WORKER_NODE>/health/alive
# Повертає: OK

# Тест Readiness probe (перевірка зв'язку між VM1-worker та VM2-db)
curl http://<IP_WORKER_NODE>/health/ready
# Повертає: OK
```
